## 四、密码修改权限修复

### 4.1 问题描述

**修复日期**: 2026-05-17  
**问题描述**: sec_admin和audit账户无法通过前端修改密码  
**修复状态**: ✅ 已修复

### 4.2 问题根源

问题出在**路由权限配置**上：

**问题位置**：`internal/api/router.go:135`

```go
// 原配置（有问题）
operators.POST("/:id/password", middleware.RequirePermission("USER_MANAGE"), r.operatorHandler.ChangePassword)
```

**问题分析**：
1. 路由要求 `USER_MANAGE` 权限
2. SEC_ADMIN和AUDITOR角色没有 `USER_MANAGE` 权限
3. 导致这两个角色无法修改密码

### 4.3 修复方案

**修复位置**: `internal/api/router.go:135`

```go
// 修复后配置
operators.POST("/:id/password", r.operatorHandler.ChangePassword)
```

**修复内容**:
1. ✅ 移除路由层的 `USER_MANAGE` 权限要求
2. ✅ 在Handler内部实现更精细的权限控制
3. ✅ 允许所有认证用户修改自己的密码
4. ✅ SEC_ADMIN和SUPER_ADMIN可以重置他人密码

**验证结果**: ✅ 通过
